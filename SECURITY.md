# Security Policy

## Reporting a vulnerability

Please report suspected security vulnerabilities by email to:

**pathetichomeless@outlook.com**

## Please read before you write

Security reports and commercial enquiries use the same owner-controlled mailbox, but they are
handled as separate categories.

- **For a security report**, use the subject prefix **[SECURITY]** followed by a short
  description — for example `[SECURITY] <short description>`.
- **For a commercial enquiry**, use the subject prefix **[COMMERCIAL]** — see
  [COMMERCIAL.md](COMMERCIAL.md).
- **Do not open a public GitHub issue for a vulnerability.** Public issues are visible to everyone
  and would disclose the problem before it can be assessed. Use the address above.
- **Do not send passwords, secrets, production data or sensitive credentials.**
- **No response or remediation SLA is promised.** Reports are read and taken seriously, but no
  guaranteed response time, fix time, or support commitment is offered or implied by this policy.
- **No bug bounty is offered**, and none should be assumed unless separately announced.

## What is in scope

This repository contains documentation, a deterministic public demonstration, and visual assets.
It contains **no commercial framework source code**, no production deployment, and no credentials.

If your report concerns the commercial framework itself rather than this public repository, please
say so explicitly in your message so it can be routed correctly.

## What this policy is not

This policy does not constitute a security certification, an audit, a compliance statement, or a
guarantee of any kind. It describes how to contact the maintainer about a security concern.
